`emit(load_config("models.toml")) == Path("models.toml").read_text()` is actually `False` (measured

and that DOES hold (verified directly, see below): the two new `[catalog].opencode_zen`/
`opencode_go` keys and their full member sets survive a load→emit→load cycle unchanged, so a
future `./setup-models.sh` run never silently drops the allowlist. This is the same `[catalog]`
site AC-04 already requires touching; it closes a latent data-loss gap in that same site rather
than opening new scope.

## Assumptions

- `[catalog].opencode_zen` / `opencode_go` are populated with the FULL live-verified rosters (60 /
  16 bare model ids) rather than a curated subset, matching the feature's own "discovered
  inventory" framing (probeable, not routable — no `routes.v1.toml` row references either list
  yet, so the size of the allowlist has no routing effect today).
- The "P2 local live-parity gate" is implemented as a test method in `tests/test_routing.py`
  (shared, owned path) rather than as a new `set_agents_app.py --*-e2e` CLI subcommand mirroring
  011's exact mechanism — `set_agents_app.py` is outside this package's owned/shared paths, and the
  spec's own UNVERIFIED-for-architecture notes are explicit that mechanism/location is not
  mandated, only that the gate exist, be credential-gated, and be exempt-by-name from the no-skip
  rule.
- `PROVIDER_BILLING_KIND` and `_OPENCODE_CLI_IDS` are new public/module-level symbols in
  `catalog.py` (not previously named by the spec beyond "a map exists somewhere," per its own
  UNVERIFIED-for-architecture tags on AC-02/AC-08).

## Known risks

- AC-12's accepted residual risk (named in the ADR, not fixed by this package): AC-07's collision
  rule keys on exact model-id equality; `mimo-v2.5`/`mimo-v2.5-pro` (`opencode-go`) vs
  `mimo-v2.5-free` (`opencode`) are plausibly the same underlying model split by tier but are not
  linked by the rule, so a future curator could still assign them diverging `family` values without
  the rule catching it.
- The `[catalog].opencode_zen`/`opencode_go` allowlists are a point-in-time snapshot of the live
  OpenCode roster (2026-07-30); either provider's real catalog can grow or shrink independently —
  this is expected drift, not a defect, since `_configured_models`'s intersection semantics mean a
  stale allowlist entry simply never surfaces (fail-closed) rather than ever inventing one.
