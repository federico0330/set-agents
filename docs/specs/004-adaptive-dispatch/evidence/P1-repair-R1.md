## Design decisions taken inside the contract

- **CONTEXT_UNRESOLVED vs. `NO_ELIGIBLE_ROUTE`/`CONTEXT_MISSING`**: `CONTEXT_UNRESOLVED` fires ONLY when
  (a) no explicit `feature_id` was given, (b) the harness cannot narrow default resolution to exactly one
  actively-executing package, AND (c) the task actually needs context. An explicit-but-invalid
  `feature_id`/`package_id` still degrades to plain `False` (contract text: "no resolvable package ⇒
  context flags false, conservative") — `CONTEXT_UNRESOLVED` is specific to the ambiguous-default case.
- **Default resolution key**: switched from "exactly one non-terminal FEATURE" (phase-based) to "exactly
  one feature whose CURRENT PACKAGE is non-terminal" (status-based) — a feature can sit at
  `PACKAGE_ACCEPTED` for its just-finished package while genuinely done contributing candidates, even
  though its overall phase isn't `DONE`/`BLOCKED` yet.
- **Freshness reference**: pack mtime is compared against the package's own `updated_at`, falling back to
  the feature doc's top-level `updated_at` when the package-level one is absent (observed to be `None` in
  current production state files) — never invented from a missing value.
- **`REVIEW_PROVIDER_CONFLICT` vs. `REVIEW_FAMILY_CONFLICT`**: both are hard exclusions now; the 003
  different-provider sort-key preference is harmless leftover (all surviving reviewer candidates already
  have a different provider once `REVIEW_PROVIDER_CONFLICT` filters), left in place rather than removed as
  an unrelated cleanup.
- **F07's CLI root seam**: lives entirely in `set_agents_app.py` (`SET_AGENTS_ROUTING_TEST_ROOT`), mirroring
  the existing `SET_AGENTS_ROOT`/`SET_AGENTS_STATE` precedent already in this file. `routing_core` itself
  never reads any environment variable for its production root (ADR-0006 invariant preserved).
